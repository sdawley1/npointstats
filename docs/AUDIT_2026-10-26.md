# Audit and refactor report — 2026-10-26

Scope: the original `n_point_statistics` scripts (snapshot commit `363ae8f`,
~7,000 lines, no tests, no packaging), refactored into the `npointstats`
package on branch `refactor/v0.1`.

## Summary

- **46 defects** were logged in [`DEFECTS.md`](../DEFECTS.md) (D-001 … D-046).
  - 45 are fixed. Each fix has a `test_regression_D###_*` test, and every test
    was first shown to fail against the original code; the failing output is
    recorded in its entry.
  - D-041 collects defects in modules that were deleted instead of fixed.
- The defects that changed numerical results:
  - S(k) and g₂ were wrong in non-orthogonal boxes (D-014, D-015).
  - g₂ was biased by O(dr/r) and reported at bin upper edges (D-019); it read
    2.5 % low at contact for 2D RSA.
  - g₂ bin widths were rescaled by L (D-017), and its range ignored `max_l`
    and exceeded the minimum-image limit (D-018).
  - The CPU S(k) sampled one quadrant/octant only (D-011), and the large-|k|
    shells were incomplete (D-012).
  - The last radial bin was dropped, and unsorted input was mis-binned (D-002).
  - Ensembles with different boxes were averaged element-wise (D-009).
  - Number-variance windows got a stray z coordinate in 2D and were not
    reproducible (D-022).
  - Theory code: a square/cube root in ρ(η) (D-034), wrong Jacobians (D-035),
    Lado sums that dropped a node (D-037), the ρ-convention mismatch (D-039),
    and small-k cancellation (D-045).
- Scaling: g₂ (O(N²) memory, D-020) and the JAX S(k) (O(M·N) memory, D-013)
  could not run on the group's N = 10⁵ configurations. Both now run in bounded
  memory.

## Real-data cross-check

Ensemble: `CONFIGURATIONS/SATURATED_RSA/RSA-2D-N_1000-rho_1.0/patterns`
(50 members, L = 31.62, read-only).

- **S(k):** the old and new codes agree to **6×10⁻¹²** on the 14,710 wave
  vectors that both sample. This covers the first 10 members; the old code
  samples only n ≥ 0.
- **g₂:** the old and new values differ by exactly the shell-volume ratio of
  D-019 times N/(N−1). For example, the bin [1.00, 1.05) reads 1.320 old and
  1.354 new, and the old value × correction = 1.3536.
- **CLI:** `npointstats -d … -s sf g2 nv -j 4` runs on all 50 members in
  2.4 s wall time with 86 MB peak RSS.

How to read the table:
- **g₂, all pairs** (r_max = L/2; the old code always did this): the time is
  the same as before and memory is 14× lower at N = 3×10⁴. The old code needs
  ~80 GB at N = 10⁵, so it was not run there.
- **g₂, defaults** (`g2_default`, r_max = 10 mean spacings): 18× faster than
  the old code at N = 10⁴, and N = 10⁵ takes 2.8 s.
- **S(k):** the new code samples the full ball |k| ≤ k_max, which is about
  3× more vectors than the old JAX quadrant. It is still 2–17× faster and
  uses 2–43× less memory. The old JAX path needs 5.2 GB at N = 10⁴ and ~50 GB
  at N = 10⁵.
- Not shown: FINUFFT's default thread count (all 192 cores) made a 2D
  N = 3000 transform take 18 s instead of 0.07 s on a shared node. The package
  therefore pins `nthreads=1`.
- Two optimisations were measured during the refactor:
  - **Bin indexing:** binning pairs with `searchsorted` took 70 % of
    all-pairs g₂ time. It was replaced by O(1) uniform-bin indexing,
    property-tested against `searchsorted`.
  - **Dense blocked g₂:** a blocked dense NumPy g₂ was benchmarked and
    rejected, because it was slower than the KD-tree path.

## Testing

- **Size:** ~390 tests; with one thread each, the suite takes ~20 s on a
  login node.
- **Tests:**
  - **Unit:** geometry, readers/writers, binning, crystals' Bragg peaks
    (square, triangular in a rhombic cell, FCC), Poisson limits, error
    contracts.
  - **Property (Hypothesis):**
    - FINUFFT matches the direct sum.
    - Translation, permutation, lattice-translation and scale invariance;
      S(k) = S(−k).
    - Minimum image and pair counts match brute-force image searches in
      random triclinic boxes.
    - Write→read round trips are bit-exact.
    - Binning conserves counts and matches `searchsorted`.
    - Theory sum rules and diameter scaling.
  - **Integration:**
    - Window-sampled σ²(R) matches the exact S(k) torus identity, per
      configuration, in d = 1, 2, 3.
    - Perturbed-lattice S(k) matches its analytic ensemble limit.
    - The CLI runs end to end; `--jobs 2` reproduces `--jobs 1` exactly;
      files round-trip.
  - **Regression:** one or more per defect.
- **Coverage:** 97 % line coverage on `src/npointstats`. Thorough mode is
  `pytest --hypothesis-profile=thorough`.

## Known limitations

- r_max (g₂) and window radii (σ²) are capped at the cell's inscribed radius,
  where minimum-image statistics stop being well defined.
- With r_max ≈ L/2, g₂ is inherently O(N²) in time (memory stays bounded).
- `method="nufft"` supports d ≤ 3; `method="direct"` works in any d.
- The LSTJ reader follows the original parser's layout. No sample file was
  available to verify it, but it checks the header N against the number of
  points read.
- `number_variance_from_sk(..., ideal_tail=True)` assumes S(k) = 1 beyond
  k_max. That is wrong for crystals, so use a large k_max or
  `ideal_tail=False` for them.
